## 共享契约（每课实现者必读）

1. **复制前进（copy-forward）**：第 N 课以第 N−1 课的 `src/` 为基线整体复制，再叠加本课新能力。每课是当课阶段的完整快照——「本课的全部代码」就在本课目录里，读者不用跳包。行数随课程自然增长（时间线增长图的叙事基础）。
2. **每课交付物**：`lessons/<id>-<slug>/`（package.json 名 `@learn-dsh/<id>-<slug>`、src/、README.md、lesson.yaml）+ 测试（vitest，只测本课**新增**行为，前进时保留旧测试且必须继续通过）+ 可跑演示（`pnpm --filter @learn-dsh/<id>-<slug> dev`，无 API key，mock 模型剧本）。
3. **工具一律 `defineTool` 定义**（统计口径 `= defineTool(`）。
4. **README 三段式**：为什么（入门主线）/ 跑起来（命令 + 预期输出 + 代码阅读顺序 + 「改两个地方感受一下」）/ 看真码（进阶导读）+ 术语对照表。纯中文，术语保留英文。以 s01 README 为形态基准。
5. **lesson.yaml 字段**：`id` `stage` `slug` `title` `idea` `lines: 0` `tools: 0` `dsh: [{label, url}]` `verifiedDshVersion: 0.1.0-rc.5`。dsh 链接一律 `https://github.com/deepseek-ai/deepseek-harness/tree/master/<本地已验证存在的路径>`；**写链接前必须 `ls` 本地 dsh 仓（/Users/lotus-7/Documents/GitHub/deepseek-harness）确认路径存在**，禁止引用 docs/subsystems/*.md（该目录只有 README，architecture.md 里的链接是悬空的）。
6. **验收命令**（每课提交前全过）：`pnpm test`、`pnpm run sync && git diff --exit-code`（只允许 lesson.yaml 的 lines/tools 变化）、`pnpm site:build`、`pnpm --filter @learn-dsh/<id>-<slug> dev`。
7. **提交**：一课一提交，`feat(<id>): <一句话>`。文件恰好一个尾换行。
8. **sidebar 不归实现者管**：全部 16 课完成后由控制者一次性加 sidebar 行。

## 逐课规格

### 阶段一（续）

**s02 tools** · 工具 = schema + 注册表 + 守卫执行管线
- 代码：在 s01 基础上引入 `ToolRegistry`（register/lookup，重名报错、未知名响亮报错）与执行管线：参数校验（required/type 的轻量 JSON-Schema 检查）→ pre-execute 钩子（可否决，否决以文本结果回喂模型）→ execute → post-execute 钩子。守卫否决与校验失败都是**喂回模型的 tool 结果**，不是进程崩溃。
- 演示：剧本让模型先发坏参数 → 收到校验错误 → 修正重试成功。
- dsh：`packages/core/tools`（src/schema.ts、invariant.ts）+ `docs/architecture.md`（Turn flow 的 tools/pre-execute → execute → post-execute）+ `docs/cookbook/adding-a-tool.md`。

**s03 session-log** · append-only 事件日志是模型的记忆与真理之源
- 代码：`SessionEvent` 判别联合（user/message、assistant/message、assistant/tool-call、tool/result、turn/start、turn/end）；`SessionLog.append()` 只增不改；`deriveMessages()` 从事件投影模型可见历史；`runLoop` 改为「写事件 → 派生请求」。核心断言：派生消息 === 实际发给模型的消息（model-visible means logged 的教学版）。附 `fork(boundary)`。
- 演示：同 s01 剧本，但打印事件流 + 证明 replay 重建出同样的派生历史。
- dsh：`packages/core/session` + `docs/architecture.md`（Session log 一节）。

### 阶段二

**s04 permission** · 权限与审批：工具不是想跑就能跑
- 代码：权限策略表（工具名 → allow/deny/ask）+ `askUser` 回调注入；实现为 s02 管线的 pre-execute 守卫；拒绝与「用户拒绝」以结构化文本回喂。演示「危险工具」被 deny → 模型改走安全路径（剧本体现）。
- dsh：`packages/interaction/user-approval`、`packages/interaction/permission-presets`、`docs/architecture.md`。

**s05 recovery** · 取消、错误恢复、turn 生命周期
- 代码：`AbortSignal` 贯穿（模型调用与工具执行都接受 signal）；工具抛错 → 错误文本作为 tool/result 回喂（可恢复），循环不崩；取消时写 turn/cancelled 事件再退出（干净收尾）。演示：会挂起的工具被超时 abort；抛错的工具被模型看到并绕开。
- dsh：`packages/core/agent`（AgentHandle、dispatch、inbox）+ `docs/architecture.md`（Turn flow 与 The agent handle）。

**s06 compaction** · 上下文压缩：在有限窗口里干无限的活
- 代码：token 预算计数（字符近似）；超阈值触发压缩：头部消息交给可注入的 `summarize`（演示用确定性摘要器，真模型课可换），产出 summary 事件（写入 s03 的日志——压缩本身是事件）+ 保留尾部窗口；派生历史 = summary + 尾部。演示长对话触发压缩后模型仍能引用早期事实。
- dsh：`packages/compaction/compaction`、`packages/compaction/compaction-basic`。

### 阶段三

**s07 cordis** · ctx、可逆 effect、typed events：一切皆插件
- 代码：迷你 Cordis：`Ctx`（`effect()` 注册即返回清理函数、`on()` 事件、`service()` 贡献服务）；typed events 用声明合并扩展 `EventMap`（TS 层面展示）；waterfall 监听链必须 `next()`。演示：挂载两个插件再卸载，观察 effect 回滚、事件解绑。
- dsh：`docs/cordis-primer.md` + `vendor/`（本地 Cordis 源码）。

**s08 plugins** · 把 s01–s06 的成果拆成插件：核心五件套如何协作
- 代码：把 s06 快照的五件套（model 适配器 / tools+session / permission / compaction / loop 驱动）改写为 s07 插件挂进 ctx；同一剧本跑出同样 transcript，但现在每步都有插件事件可拦截。展示「换一个插件 = 换一个世界」的最小例子（换 permission 插件的策略，行为即变）。
- dsh：`packages/core/`（agent-loop、tools、session 如何作为插件协作）+ `docs/architecture.md`（Cordis 一节）。

**s09 seam** · capability seam 三角色：换个 provider，整个世界跟着走
- 代码：`FsService` 接口（Definition）；`MemoryFs` 与 `RemoteFs`（模拟延迟与隔离）两个 Provider；`read_file`/`write_file`/`list_dir` 三个 Consumer 工具。配置切换 provider，工具行为整体切换，Consumer 代码零改动。演示：同一「建文件再读回」任务在两个世界各跑一遍。
- dsh：`packages/fs/fs`、`packages/fs/fs-local`、`packages/shell/shell` + `docs/architecture.md`（Capability seams 一节）。

### 阶段四

**s10 sandbox** · 沙箱与统一执行世界：本地一键换远程
- 代码：`ExecutionWorld` seam 统一 fs + subprocess；`LocalWorld`（真 child_process，受限白名单命令）与 `SandboxWorld`（进程内虚拟世界：虚拟 FS + 模拟执行，拒绝越界路径）；spawn 前策略检查（路径越界 → 拒绝并回喂）。演示同一 bash 型工具在两个世界执行同一段「脚本」。
- dsh：`packages/e2b`、`packages/subprocess`、`packages/fs/fs-sandbox`、`packages/shell/bash-sandbox`。

**s11 subagent** · 子代理：委派与隔离
- 代码：`SubagentSeam`（spawn(task, toolset) → 私有 runLoop + 私有事件日志 + 受限工具集）；父代理的 `delegate` 工具返回子代理最终回答摘要；子代理工具集默认不含 delegate（防无限递归，设深度上限）。演示：父代理委派「在虚拟 FS 里统计文件」给子代理。
- dsh：`packages/subagent/subagent`、`packages/subagent/subagent-spawn-in-process`、`packages/subagent/tool-subagent`。

**s12 skills** · 技能系统与后台工作流
- 代码：`Skill` = 名称 + instructions + 可选附加工具；注册表 + `load_skill` 工具（加载后 instructions 注入 system 段——经 s03 日志的 system/message 事件）；后台 `Job` 注册表 + `start_job`/`collect_job` 工具（异步推进、状态查询）。演示：模型加载「csv 技能」后按技能规程完成任务，期间挂一个后台 job 并取回结果。
- dsh：`packages/skill/skill`、`packages/skill/skill-filesystem`、`packages/workflow/workflow`、`packages/workflow/workflow-worker-thread`。

**s13 persistence** · 持久化：恢复、分叉、回放
- 代码：s03 日志落 JSONL 文件；`resume()` 重放事件重建状态后继续对话；`fork()` 从边界分叉出新会话文件；`replay()` 打印 transcript。演示：进程「重启」（新实例 resume 同一文件）后模型记得之前说过什么。
- dsh：`packages/session`（durable 持久化、SQLite SCHEMA_VERSION 的对照叙述）。

### 阶段五

**s14 bundles** · profile 与 bundle：同一批插件组装出不同产品
- 代码：层叠组装：base 层（五件套插件表）+ profile 层（`full`：全工具 + ask 权限；`safe`：只读工具 + deny 危险 + 预压缩更激进）+ patch 覆盖（改一行配置换策略）。同一份插件代码，两个 profile 跑出两个产品形态。演示两个 profile 对同一请求的不同行为。
- dsh：`packages/bundle/base`、`packages/boot/app-boot`（profile 组装）+ `docs/architecture.md`（Profiles and bundles 一节）。

**s15 bridge** · 桥接课：用真实 `@deepseek-ai/dsh-*` 包组装自己的 mini harness
- 前置调查（实现者必做）：`npm view` 确认要用的包真实发布及其版本（上游 0.1.0-rc.5 已公开发布 dsh family）；读本地 dsh 仓 `examples/headless-agent`、`examples/acp-agent` 与 `packages/llm` 的 adapter seam，确认**无 key 可跑**的组装路径（自写剧本式 llm adapter 插件挂在 llm seam 上）。
- 代码：workspace 引真实 npm 包，组装最小 agent（session + tools + loop + 剧本 adapter），跑通一次工具往返。
- 兜底：若公开包 API 无法无 key 运转，退化为「类型级桥接」（依赖真实包、import 其类型与工具 schema 组装，运行时用自家 mock）并在 README 写明差距与原因——**不许虚构 API**。
- dsh：npm `@deepseek-ai/dsh-*` + 本地 `examples/`。

**s16 recap** · 全景回顾 + "Where new behavior goes" 实战地图
- 内容为主：对照表（architecture.md 的扩展点 ↔ 演示过它的课）；一个整合演示（用 s14 的 full profile 跑一条覆盖面最广的剧本）；「通向你的业务」导读（改哪个 seam、挂哪个事件）。
- dsh：`docs/architecture.md`（Where new behavior goes 表）。

## 执行机制

- 严格顺序 s02→s16（复制前进链）。每课一个实现者子代理（标准档模型），完成后控制者跑四条验收命令并抽查 dsh 事实（lesson.yaml 链接逐条对照本地 dsh 仓）。
- 每完成一个阶段（s03/s06/s09/s13/s16 后）派一个阶段审查子代理：审该阶段各课的 spec 符合度 + 代码质量 + dsh 导读准确性。
- 全部完成后：控制者加 sidebar 16 行 + `pnpm run sync` + 全量验收，派最终全分支审查（最强模型），修完合并 PR、验证部署。
- 台账：`.superpowers/sdd/progress.md` 逐课追加 `Lesson sXX: complete (commit <sha>)`。
